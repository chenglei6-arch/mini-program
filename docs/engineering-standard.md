# 工程规范

## 分支和提交

- `main`：可发布代码；`develop`：日常集成；功能使用 `feat/<name>`，修复使用 `fix/<name>`。
- 提交信息采用 Conventional Commits：`feat:`、`fix:`、`docs:`、`refactor:`、`test:`、`chore:`。
- 合并前必须通过静态检查、冒烟测试和接口契约检查。

## 页面和服务边界

- WXML 只负责展示和事件绑定。
- 页面 JS 负责页面状态，不负责 URL 拼接、Token 管理和响应解析。
- `services/` 负责业务语义；`utils/request.js` 负责传输层。
- 接口字段使用后端契约中的命名；展示字段在服务层适配。

## 组件选型

- 基础表单、单元格、弹窗和反馈优先采用腾讯官方 `weui-miniprogram`，减少自定义基础组件维护成本。
- 轮播、扫码、震动、分享等能力优先使用微信原生组件/API；只有业务组合交互才放入 `components/`。
- 引入第三方组件前检查许可证、基础库兼容性、包体积和最近维护状态，禁止直接复制无法追溯来源的代码。

## 安全和合规

- Token 仅存本地存储，日志中不得打印 Token、手机号、二维码原文或支付信息。
- 付费和公益数据以服务端为准，客户端只能展示，不能计算最终金额或授予权益。
- 用户动态、排行榜和分享内容必须支持匿名化、撤回和内容审核。
